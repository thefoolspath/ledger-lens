# Contributing

LedgerLens is in a research-and-planning phase.

## Documentation changes

- Use English, UTF-8, relative Markdown links, and ISO dates.
- Mark claims as fact, inference, recommendation, or unresolved where ambiguity matters.
- Prefer official documentation, standards, provider terms, and upstream release notes.
- Record source URL, version/date, and access date for time-sensitive evidence.
- Link architecture changes to an ADR and supporting research.
- Do not duplicate detailed rules across documents; link to the source of truth.

## Data safety

Contributions must use synthetic names, references, quantities, prices, and documents. A redacted real slip is still prohibited as a tracked fixture.

## Decision changes

Capture unaccepted feedback in `docs/project/ISSUE_AND_CHANGE_REQUESTS.md`. Promote it into product scope, an ADR, or an active plan only after review.
