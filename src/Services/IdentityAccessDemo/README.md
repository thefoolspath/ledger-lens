# IdentityAccessDemo structure demo

This isolated service demonstrates two user-data operations: `UsersCreate` (command) and `UsersGetOne` (query). Domain owns the user invariant; Application owns handlers, typed results and narrow persistence ports; Database owns EF records/model; Infrastructure owns mapping and PostgreSQL access; Migrations owns schema changes; API owns HTTP mapping and exception handling. A caller supplies a UUIDv7 `requestId` to `UsersCreate`; the unique request ID allows a matching retry to return the same created user after a lost response.

The API remains an internal Aspire resource. The Angular `/identity-access-demo` feature sends synthetic requests to `/api/identity-demo/v1/users/...`; its development proxy forwards `/api` to the Gateway, which removes `/api/identity-demo` and routes to `identity-demo-api`. The service reads and writes its own new `ledgerlens_identity_demo` PostgreSQL database. The existing `ledgerlens_identity` database is left untouched. This loopback-only demo route is unauthenticated; routing through the Gateway does not implement authentication or authorization. Google OIDC, sessions, roles, and resource catalogs remain outside this demo.
